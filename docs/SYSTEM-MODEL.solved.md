# 系统模型 · 参考答案（dsh web 朗读）

> 这是同一份模板的完整填法，用来对照，不是用来背的。
> 重点看「不变量」那节——它直接决定你验收什么。

---

## 1. 外部契约

- **入口（用户动作）**
  - `Alt` + 点击正文 → 从所点那块的第一句开始读
  - 面板勾选「自动朗读」→ 新回复完成后自动读
  - `⏹` / `Alt+X` → 立即停止
  - 点/拖进度条 → 跳到对应句
  - 调语速 / 音量 / 音色 → 即时生效
- **出口（用户能看到）**
  - 声音（云健，或系统语音）
  - 逐字高亮 + 自动滚动
  - 面板状态文字、toast
  - `__dshAutoLog`（调试用，不是给用户看的）
- **明确不承诺**
  - 不读思考区（只读明确标出的回答）
  - 平台 DOM 改版后会**静默不读**，不会报错
  - 本地服务不可用时回退系统语音（音质下降，但会继续读）
  - 不保证跨会话连续阅读

## 2. 状态

配置项（不是状态）：`rate`、`volume`、`voice`、`local`、`auto`——设了就一直在。

| 状态 | 由什么进入 | 由什么离开 | 非法/异常组合 |
|---|---|---|---|
| idle | 读完、停止、切会话 | 点朗读 / 自动触发 | — |
| playing | 点朗读 / 自动触发 | finish、stop、被新回复抢占 | 说在播但没有音源（卡死） |
| paused | 点暂停 | 继续、停止 | 暂停时新回复抢占未处理 |
| seeking | 拖进度条 | 松手重排 | 拖动时旧队列没取消，双音轨 |

## 3. 数据

| 数据 | 存在哪 | 谁写 | 什么时候清 | 不清会怎样 |
|---|---|---|---|---|
| `sentences` / `chunks` | 内存 | `playTextFrom` | 下次播放 | 体积小，可忽略 |
| `autoQueue` / `autoSeen` / `autoBaseline` | 内存 | `scanAuto` | 换会话、关开关 | 误读旧消息 |
| `localUrls`（blob） | 浏览器内存 | `localPrefetch` | `stop()` | 内存上涨 |
| 设置（语速/音量/音色/本地/自动） | localStorage | 面板 | 手动清 | 设置丢失 |
| TTS 音频与时间戳 | 服务端磁盘 `%TEMP%` | `server.mjs` | 7 天 / 300MB | 占磁盘 |
| `__dshAutoLog` | 内存 | `autoLog` | 超过 50 条 | 无 |

## 4. 失败模式

| 哪一步 | 失败表现 | 能恢复吗 | 用户看到什么 |
|---|---|---|---|
| 本地服务没起 | fetch 失败 | 回退系统语音 | toast「已切回系统语音」 |
| 语音被浏览器拦 | `play()` reject | 回退 | 同上 |
| 找不到回答容器 | 检测跳过 | 下次扫描 | 什么都不发生 |
| 平台 DOM 改版 | 检测不到新回复 | 要改代码 | 什么都不发生（最危险） |
| 端口被占 | 服务起不来 | 换端口 | 启动窗口报错 |
| 长回复 | 读很久 | 新回复抢占 / 手动停 | 声音一直念 |

## 5. 不变量

| # | 不变量 | 怎么验证（探针） | 验证过吗 |
|---|---|---|---|
| 1 | 同一时刻只有一个音源 | `synth.speaking` + `localAudio` 状态 | 是（卡死那轮） |
| 2 | 每条回复最多自动读一次 | 日志里没有重复 `play` | 是 |
| 3 | 只从回答容器取文本 | 读出来的内容里没有思考 | 是 |
| 4 | 停止后不再有排队播放 | `stop` 之后没有新的 `play` | 是 |
| 5 | 换会话不读旧消息 | `new-session` 之后没有 `play` | 是 |

## 6. 未知清单（真正还没验证的）

- 展开思考过程时，回答容器还能不能认出来（N9 没实测）
- 同一条回复「重新生成」时，turn 号会不会复用 → 可能漏读
- 开两个标签页时，两个实例会不会互相抢音频
- 极长文本（>2000 字）时，服务端时间戳和音频还对得上吗
