# 回归清单

> 目的：每次改动后，用 3 分钟确认没把已经修好的东西改坏。
>
> 能机器判定的（切句、分段、偏移、版本比较）已经写进 `npm test`；
> 出声、高亮、面板这些只能人耳人眼过的，走这份清单。

## 怎么用

1. **每次 commit 前**：跑「A. 冒烟 10 条」，3 分钟。
2. **每次发版前**：跑全量 + 「M. 发版检查」。
3. **挂了**：记编号 + 版本号 + Console + 截图，按文末「报障包」一次性发出来，别一条一条问。

约定：每条前面的编号（A1、D3…）在报障时直接引用。

---

## 0. 不变量（每次改动都要确认）

这些是「一旦不成立，就是 bug」的东西。验收时先过这 5 条，再看功能。

| # | 不变量 | 怎么验 | 对应条目 |
|---|---|---|---|
| INV1 | 同一时刻只有一个音源 | 播放中切本地/系统、被抢占时，不该同时出声 | A5、N5 |
| INV2 | 每条回复最多自动读一次 | 日志里同一条没有两次 `play` | N4 |
| INV3 | 只从回答容器取文本 | 读出来的内容里没有思考 | N3、N9 |
| INV4 | 停止后不再有排队播放 | `stop` 之后没有新的 `play` | N7 |
| INV5 | 换会话不读旧消息 | `new-session` 之后没有 `play` | N8 |
| INV6 | 高亮只画在当前会话、仍 connected 的元素上 | 切会话后 `boxDisplay` 应为 `none` | N11 |

> 加新功能时先问：它会不会破坏上面某一条？会，就补一条用例。

## L. 已知限制（出现不算 bug，别浪费一轮）

- `onboundary` 在少数语音引擎不触发 → 逐字高亮停在段首
- 语音列表随环境变化（Edge 可能几百个在线音色）
- 长文本的音质和停顿由系统语音决定
- GitHub raw 有几分钟 CDN 缓存，更新检查可能延迟
- `deepElementFromPoint` 最多穿透 5 层 shadow DOM
- 自动朗读只认 `data-chat-turn` / `data-turn-process-answer` / `data-turn-tail`；dsh 改结构就会失效（失效表现是「不读」，不是「乱读」）

## O. 报障包（一次性发，别一条一条问）

```
版本：v1.16.0（面板/Console 里抄）
编号：D1、K4（能对上清单就写编号）
现象：点第 5 段，从第 1 段开始读
复现：刷新 → 打开任意长回复 → Alt+点第 5 段（每次都这样 / 偶发）
期望：从第 5 段第一句开始
实际：从第 1 段开始，进度条显示第 1 段
Console：__dshProbe = ? / __dshState.sentences.length = ? / 报错原文
最近改动：v1.15.18 调了 CHUNK_CHARS
```

一次把同一主题下的**所有**现象列全，让 AI 做根因分析，而不是猜最近一处。
